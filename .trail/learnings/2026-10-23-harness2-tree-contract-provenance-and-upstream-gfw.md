## Decided
Harness2-tree contract 1 supports surface=codex|opencode through the shared materialization writer, verification and recovery. The harness root is destination/content and receipt.json remains beside it. The adapter composes all resolved injected instructions in order, copies captured skills and allowed resources, adds triggers, and records per-source compose/copy/trigger/skill-name/unmapped mappings. Generated backing is the SHA-256 of generated bytes. Explicit memory is pinned per export; explicit subagent files are accepted, but session roles are not converted. Node validates caps, metadata, hooks and script references; the manual Python workflow validates pinned upstream source without executing archived scripts.

## Tried and ruled out
Reusing repository AGENTS.md as harness content would leak repository rules into a selected profile; it is explicitly unmapped. Fabricating missing memory, subagents or host-only skill bytes is unsupported. Universal byte-preservation and native runtime claims would be false for composed output, so those receipt claims stay unverified or unsupported.

## Watch out
Required local skills retain bytes in composition, captured host skills may retain them in hostReferences, and native packages need package-file lookup. OpenCode cap counting includes six separator characters even when optional always-on files are absent. Upstream read_tree emits platform-native keys on Windows; the compatibility checker converts keys to POSIX before validate and checks the skill/script census to avoid false success. Tested pinned source at 1cfe254e8d25b15f37048c3730134686abe60335 using local Python 3.14; the manual CI job selects Python 3.12.

Trail check currently reports a false-positive conflict for test/materialize.test.js, calling the filesystem plan/receipt negative test a ruled-out approach. The earlier note's Tried and ruled out section mentioned the existing independent oracles positively. Keeping those oracles and changing the now-supported harness2-tree negative-test identifier to unknown-tree is intentional and preserves rejection coverage. Carry this explanation into any future commit or PR; do not delete the byte-compatibility tests to satisfy that lexical match.
