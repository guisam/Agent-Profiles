## Decided
Added docs/agent-qualification.md as the assistant-assisted front door for issue 33: one starting prompt, a small accepted intake, existing native evaluation/adoption machinery, docs/templates/agent-qualification-report.md, and a worked real pilot report at docs/examples/agent-qualification-pilot.md. It is a readable report/workflow, not a new CLI command, configuration selector, native evidence format, queue, billing system or certification engine. Basic/premium labels map to explicit supported model/role/host selections.

## Tried and ruled out
Native eligibility means no per-case regression; it can remain eligible when both arms fail, so service quality requires independent absolute gates. Unknown required cost/latency/coverage prevents readiness; fixture-only or ungraded pilot output cannot qualify a live tier. Additional timing/accounting remains cited measurements, never fabricated native metrics. A real retained qualification-report.md was produced from the existing pilot after checking completed output hashes and native identities; it needs evidence and authorizes no adoption. Source feature version 0.3.0, build and packaged-document checks, 71 relative-link checks and 100 native evaluation/promotion contract tests passed. No new model calls were launched.

## Watch out
The new flow still needs fresh-user walkthrough and full live repeated held-out/adoption/restoration validation; keep issue 33 open. Report ready-for-adoption-review is not promotion authorization or a runtime guarantee. New deployment stamps must be distinguished from tested evaluation stamps. Preserve active project instructions, permissions, other tuples and guarded restoration. Existing plans/results remain authoritative; do not introduce parallel qualification JSON schemas or tier YAML fields to implement this first assistant-assisted experience.
