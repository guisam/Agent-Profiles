## Instructions and configuration

The native instruction loader chooses the first existing global file from the OpenCode configuration directory's `AGENTS.md`, then the Claude-compatible `~/.claude/CLAUDE.md` fallback when enabled. Project filename priority is `AGENTS.md`, then enabled `CLAUDE.md`, then deprecated `CONTEXT.md`. Project discovery can be disabled. [Instruction candidates and global selection](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/session/instruction.ts#L59-L71), [project selection](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/session/instruction.ts#L109-L150).

**Ancestor detail:** the selected filename is searched from the working directory through the worktree boundary. `findUp` collects every matching ancestor; the instruction loader adds all returned paths before it stops trying other filename classes. Its comment about a first match must not be read as nearest-file-only behavior. An ancestor `AGENTS.md` can therefore suppress the `CLAUDE.md` class. Separately, reading a nested file can attach nearby instructions once per message, excluding system paths and already loaded paths. [Actual `findUp` implementation](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/core/src/fs-util.ts#L154-L165), [nested instruction attachment](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/session/instruction.ts#L171-L221).

The `instructions` configuration array adds local paths/globs and HTTP(S) URLs. Relative patterns are searched upward through the worktree; `~/` is expanded; absolute patterns use their parent directory. Missing/unreadable local instruction content and failed remote fetches become empty content rather than proof of loading. [Resolution and reads](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/session/instruction.ts#L84-L105), [path and URL loading](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/session/instruction.ts#L135-L168).

Configuration merges remote organizational defaults, global configuration, `OPENCODE_CONFIG`, project files, discovered configuration directories, then `OPENCODE_CONFIG_CONTENT`; later managed configuration and macOS managed preferences can override these. Global files load `config.json`, `opencode.json`, then `opencode.jsonc`. Project file discovery reverses its upward search; `.opencode` directories load `opencode.json` then `opencode.jsonc`. `instructions` is specially concatenated and deduplicated across sources instead of simply replaced. [Merge rule](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/config/config.ts#L40-L51), [global order](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/config/config.ts#L272-L274), [main loading order](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/config/config.ts#L370-L489), [managed overrides](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/config/config.ts#L530-L548), [path discovery](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/config/paths.ts#L10-L41).

Do not hardcode a Windows AppData path: the pinned implementation uses `xdg-basedir` for configuration and supports an overridden configuration directory. Actual Windows path resolution needs a native check. JSONC is a real user surface; upstream uses JSONC-aware editing for its global JSONC updates. An adapter must preserve comments, unrelated settings, and file ownership rather than parse/stringify arbitrary user configuration. [Global paths](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/core/src/global.ts#L1-L29), [directory override](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/core/src/global.ts#L65-L76), [JSONC update](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/config/config.ts#L656-L675).

## Native skills and duplicate names

The CLI/session implementation uses `packages/opencode/src/skill/index.ts`. Do not infer its behavior from the distinct newer core skill API. Its scan covers recursive `skills/**/SKILL.md` under global and ancestor `.claude`/`.agents` roots when enabled; `{skill,skills}/**/SKILL.md` under configuration directories; additional `skills.paths`; and downloaded `skills.urls`. It follows symlinks. Configuration directories include the global config directory, ancestor `.opencode` roots, home `.opencode`, and `OPENCODE_CONFIG_DIR`. [Patterns](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/skill/index.ts#L21-L25), [scan flags](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/skill/index.ts#L152-L186), [root discovery](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/skill/index.ts#L188-L233), [configuration roots](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/config/paths.ts#L23-L41).

**Duplicate precedence is not safely deterministic in this pin.** Each asynchronously parsed file assigns `state.skills[name]`, warning on an existing name. Loading calls these parsers with `concurrency: "unbounded"`. Inference: the last completing assignment wins; discovery order alone cannot establish a reliable project-over-global winner. No subsequent reconciliation restores a root-based order: initialization loads once, and availability only sorts the resulting values. A managed inventory should report ambiguity for duplicate names, not advertise a guaranteed winner. This inference has not been exercised against an executable. [Parse/assignment](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/skill/index.ts#L110-L150), [concurrent loading](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/skill/index.ts#L235-L245), [initialization](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/skill/index.ts#L273-L285), [availability filtering](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/skill/index.ts#L311-L324).

The pin accepts string `name` and optional string `description`; this is looser than the documentation's naming/description guidance. An adapter may deliberately retain stricter portable validation, but should identify that as its own policy. Skill availability is filtered by native permissions; discovery is not invocation evidence. [Frontmatter predicate](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/skill/index.ts#L53-L60), [permission filter](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/skill/index.ts#L316-L323).

## Prompt, identity, and lifecycle

Markdown agents load from `{agent,agents}/**/*.md`; their trimmed body becomes `prompt`. Configured agent model and prompt override those agent fields. During a model step, native environment, instructions, MCP guidance, and skills enter the system input. Final preparation uses an agent prompt when present in place of the provider's default prompt, appends system/user instructions, and exposes a plugin transformation hook. Thus a stored profile is neither the entire rendered prompt nor proof of runtime compliance. [Markdown agents](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/config/agent.ts#L11-L33), [agent overrides](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/agent/agent.ts#L267-L291), [step assembly](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/session/prompt.ts#L1255-L1285), [final preparation](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/session/llm/request.ts#L56-L77).

Model identity is a provider/model pair, with a separate variant. Per-message resolution prefers explicit input model, then the agent's model, then the current session model; current-model fallback can use a previous user message or the provider default. Record declared selection separately from observed request identity. The same model label alone does not establish the provider, variant, authentication route, or rendered prompt. [Model resolution and stored message fields](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/session/prompt.ts#L614-L665), [CLI provider/model parsing](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/cli/cmd/run.ts#L31-L38).

Proposed repository mapping: retain the exact provider/model string and `host: opencode`; do not strip or infer its provider. Use `identity-source: user` for operator-selected identity, reserving `host-stated` for identity actually supplied by the host. Unknown identity follows existing configuration fallback. Map a native agent to a repository role only through explicit user/agent assignment; do not infer `build = worker`. Each child needs its own explicit role and identity provenance. Record variants as external evaluation conditions for this slice, without introducing a stamp schema field. These are adapter policy proposals, not upstream guarantees or implemented behavior.

Native primary-agent switching exists within a session; it must not be described as clearing history. The message creation path accepts a new agent while resolving an existing session model. Subagents use a separate child session with `parentID`; supplying `task_id` can reuse a previous child session. A child uses its own configured model or inherits the parent assistant's provider/model (and variant when inheriting). These are distinct boundaries from the repository's task/profile lifecycle. [Agent usage documentation](https://opencode.ai/docs/agents/), [per-message agent selection](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/session/prompt.ts#L635-L665), [child creation/reuse and model inheritance](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/tool/task.ts#L130-L211).

For CLI runs, `--session` reuses a session, `--continue` selects an existing root session, and `--fork` forks an existing session. With none selected, the shown CLI path creates a session. Inference: an adapter cannot achieve fresh context by rewriting bootstrap text or switching agents; require a new native session for a fresh profile/task boundary and separately record when this was actually observed. A new session also does not prove process-level configuration/discovery caches were refreshed. [Run session selection](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/cli/cmd/run.ts#L457-L530), [instance-cached skill discovery](https://github.com/anomalyco/opencode/blob/148842ef7cb1bc34192b3fff57d0f9721ab9c801/packages/opencode/src/skill/index.ts#L259-L285).

## Bounded adapter mechanism proposed for review

The smallest local candidate is a distinct OpenCode marker namespace inside shared `AGENTS.md`. That avoids configuration edits and can preserve Codex's managed span, but **both hosts read both blocks**. It is suitable only for a deliberately shared neutral protocol or explicit host-conditional guidance; markers provide installer ownership, not native host isolation. Installation, update, inspection, and uninstall must identify the intended host's span independently. A generic single-span detector cannot establish which host was configured. The mechanism remains proposed until loading fixtures establish its behavior.

If isolated host bootstrap content is needed, the alternative first slice is host-owned markdown referenced through native `instructions` from an owned `.opencode/opencode.json` when that file is absent. Confirm relative resolution with a native smoke test before declaring support. If that config already exists, preserve it byte-for-byte until a JSONC-aware, ownership-aware edit is available; do not overwrite a user config or silently shadow its `.jsonc` peer. Refusing existing user configuration is only a bounded first slice, not final issue acceptance: an ownership-aware update/removal path would still be required. This preserves Codex's existing managed `AGENTS.md` block. It still coexists with ordinary native `AGENTS.md` loading: configured instructions do not disable that source.

Initial support should cover explicit OpenCode selection, repository bootstrap installation, bounded metadata-only native skill inventory, and honest lifecycle guidance. Do not add automatic model launches, provider setup, agent rewriting, or claims of rendered-prompt/native-invocation verification. Later executable checks should cover config precedence (including an existing JSONC peer), nested instruction loading, duplicate skills, independent Codex/OpenCode uninstall, agent switching, new sessions, resumed children, and provider/model/variant identity.
